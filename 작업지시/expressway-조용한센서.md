# 작업 지시: 한국도로공사 AI 활용 아이디어 — 조용한 센서: 한산한 것인가 고장인가

Claude Code에게 주는 작업 지시서다. 이 파일을 먼저 끝까지 읽고 순서대로 진행한다.

## 1. 목표
차량검지기·풍속계·안개(시정) 센서가 "이상 없음/0대/낮은 값"을 낼 때, **정말 한산·잔잔·맑은 것인지 센서가 멈춘 것인지**를 이웃 센서와 도로 연결망으로 가려내 점검 대상 목록을 만드는 **개념 증명(PoC)과 제안서**를 만든다.
대표 사례는 차량검지기이고, 같은 틀이 풍속계(값 고정)와 안개 센서(순간 가림)에도 적용된다는 점을 보인다.

## 2. 출처와 배경
- 출처: `expressway/` 40회차 3번(핵심), 18회차 5번, 45회차 2번, 47회차 5번(11월 공모전 아티팩트 도로공사 4위 묶음 안).
- 평가 근거: `evaluations/expressway.md`, `research/awards-2021-2025.md`.
- 공고 원문(`research/awards-2021-2025.md`의 한국도로공사 공고 링크)에서 제출 형식·분량·마감을 먼저 확인하고 다르면 공고를 따른다.
- 관련 선행: 같은 공모에 대한 유관 사례(2024 미래한국 아이디어 공모전)는 사고 신고 방향 혼선 해결이었다. 이번 안은 안전 정보의 **신뢰도 자체**를 다룬다는 점으로 차별화한다.

## 3. 문제 정의
- 심야 검지값이 0이면 차량이 없는 것인지 검지기가 멎은 것인지 알 수 없어 교통정보·전광판 안내가 틀릴 수 있다.
- 풍속계가 낮은 값으로 고정되면 횡풍 위험이 가려진다. 안개 센서 앞을 대형차가 가리면 국지 안개로 잘못 읽힌다.
- 핵심 질문: **이웃 구간에서 차량이 들어왔다면 이 센서 앞에 몇 대가 도달해야 하는데, 0대라면 고장 확률은?**

## 4. 접근
1. **기대 통과 대수 모형**: 상류 센서의 통과 기록을 구간 주행시간 분포만큼 지연시켜 하류 기대 대수를 구한다. 분기점·휴게소·IC 유출입은 비율 파라미터로 반영하고 **불확실성 구간**을 같이 계산한다.
2. **판정**: 관측값이 기대 구간 아래에 지속되면 "점검 후보", 기대 구간 안이면 "정상 한산", 기대 자체의 불확실성이 크면 "판정 보류"로 분리. 세 번째 범주를 반드시 둔다.
3. **다른 센서에 확장**: 풍속계는 값의 분산이 0에 가까운 구간이 이웃 풍속계·기상 관측과 어긋나는지, 안개 센서는 짧은 이상이 차량 통과 시각과 겹치는지를 같은 틀(독립 정보와 대조)로 처리. 지속 저시정은 자동 해제하지 않는다.
4. **공사 통제·정비 기록**은 별도 조건으로 처리(통제 중 0대는 정상).

## 5. 만들 것
```
sensor-project/
  README.md                  # 실행법, 가정, 한계
  src/network.py             # 노선 연결망(노드=센서, 간선=구간, 분기 비율)
  src/simulate.py            # 합성 교통 + 고장 주입 생성기
  src/detect.py              # 기대 통과 대수·판정(점검 후보/정상 한산/보류)
  src/evaluate.py            # 탐지 지연, 오경보율, 미탐률 계산
  tests/
  notebooks 또는 output/     # 그래프와 표
  report/proposal.md         # 제안서 본문
  report/appendix_ai_log.md  # AI 사용 기록
```
공개 데이터가 없으므로 **전부 합성 데이터로 시연**한다. 실제 도로공사 데이터(구간별 검지기 집계, 노선 연결망, 수리 이력)는 "협약 시 제공받을 후보"로만 쓴다.

## 6. 합성 실험 설계
- 노선 하나(센서 20~30개, 분기·휴게소 포함), 24시간×30일, 시간대별 교통량(심야 한산 포함).
- 고장 주입 유형: 값 0 고정, 마지막 값 고정, 전송 단절, 풍속계 저값 고정, 안개 센서 순간 가림.
- **반례를 일부러 넣는다**: 실제 무교통 새벽 구간, 공사 통제 구간, 분기가 많은 구간, 안개가 차량 통과와 겹친 실제 저시정.
- 비교 기준선: "값이 0이 N분 지속되면 경보"라는 단순 규칙. 제안 모형이 기준선보다 나은 조건과 나쁜 조건을 모두 보고한다.

## 7. 평가 지표
- 고장 탐지 지연(분), 오경보율(정상 한산을 고장으로 판정), 미탐률, 보류 비율.
- 기준선 대비 개선폭. 분기 수가 늘수록 성능이 어떻게 떨어지는지 곡선으로.
- 지표와 판정 임계는 실험 전에 고정하고, 실험 후 임계를 맞춰 성능을 올리지 않는다.

## 8. 제안서 구성
1. 문제와 사례(숫자 한두 개로) 2. 접근과 AI의 역할 3. 데이터(제공 후보와 합성 시연) 4. 실험과 결과 5. 한계와 운영 방식 6. 기대 효과(과장하지 않음) 7. 부록: AI 사용 기록

## 9. AI 사용 규칙
- AI는 기대 모형의 불확실성 추정, 시계열 이상 패턴 분류, 설명 문장 초안에 쓴다. 판정 최종 책임은 관제원이며 **자동 조치나 자동 해제 기능을 만들지 않는다**.
- 모든 결과 수치는 `src/evaluate.py` 출력으로만 쓴다. AI가 말한 수치를 그대로 옮기지 않는다.
- `appendix_ai_log.md`에 AI의 틀린 제안과 수정 내용을 기록한다.

## 10. 검증 기준 (완료 조건)
- [ ] 합성 데이터 생성부터 평가까지 한 명령으로 재현된다(난수 시드 고정).
- [ ] 반례(실제 무교통, 공사 통제, 실제 저시정)에서의 오경보를 숨기지 않고 보고했다.
- [ ] "판정 보류" 범주와 그 비율이 결과에 포함돼 있다.
- [ ] 기준선보다 나쁜 조건이 있으면 한계 절에 서술했다.
- [ ] 공고 요건 확인 결과와 불일치 사항을 메모했다.

## 11. 약점과 대응 (제안서에 먼저 쓸 것)
- 분기가 많은 구간은 모형 오차가 크다 → 불확실성 구간을 표시하고 보류 범주를 둔다.
- 합성 데이터만으로는 실제 성능을 보증하지 못한다 → 시연임을 명시하고 실데이터 검증 계획을 별도 절로 쓴다.
- 평가에서 "단순 규칙으로도 된다"는 지적이 가능하다 → 기준선과의 비교 결과로 직접 답한다.
- 이웃 센서도 고장이면 판정이 흔들린다 → 연쇄 고장 시나리오를 실험에 포함한다.

## 12. 진행 방식
- 작은 단위로 커밋한다(연결망 → 생성기 → 탐지 → 평가 → 제안서). 푸시는 사용자가 요청할 때만.
- 공고 요건이나 데이터 가정이 충돌하면 임의로 정하지 말고 질문한다.
