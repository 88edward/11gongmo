# 작업 지시: AFPK 영 플래너 챌린지 — 은퇴 첫해 손실, 인출 순서가 바꾸는 잔액

Claude Code에게 주는 작업 지시서다. 이 파일을 먼저 끝까지 읽고 순서대로 진행한다.

## 1. 목표
같은 수익률도 **손실이 먼저 오는지, 이익이 먼저 오는지**에 따라 생활비를 인출하는 은퇴자의 잔액이 달라진다(수익률 순서 위험)는 점을 보여 주는 **B안 사례 보고서**를 만든다.
재무설계 6단계(범위 합의 → 자료 수집 → 진단 → 대안 → 실행 → 점검)를 한 사례로 끝까지 전개하고, **AI 결과를 검산한 과정**을 부록에 남기는 것이 핵심이다.

## 2. 출처와 배경
- 출처: `afpk/2026-11-03-round-23.md` 1번 아이디어(11월 공모전 아티팩트 AFPK 1위).
- 평가 근거: `evaluations/afpk.md`, `curated/top5.md`, `research/awards-2021-2025.md`.
- 대회 성격: 협회가 2026년을 제1회로 명시. 과거 수상작 없음. 공고 원문은 `research/awards-2021-2025.md`의 AFPK 공식 공고 링크에서 **제출 형식·분량·마감을 먼저 확인**하고 이 지시서와 다르면 공고를 따른다.

## 3. 핵심 숫자 (검산 기준값)
초기 자산 1,000만 원, 매년 말 100만 원 인출, 수익률 −20%와 +25%가 2년간 한 번씩.

| 경로 | 1년 말 | 2년 말 |
|---|---|---|
| −20% → +25% | 1,000×0.8−100 = 700 | 700×1.25−100 = 775 |
| +25% → −20% | 1,000×1.25−100 = 1,150 | 1,150×0.8−100 = 820 |

차이 45만 원. 수익률 평균이 같아도 순서가 다르면 결과가 다르다. 이 표가 코드와 보고서에서 어긋나면 작업을 멈추고 원인을 찾는다.
※ 인출 시점(연말), 세금·수수료 없음, 수익률은 연 1회 적용이라는 가정을 보고서 첫 장에 명시한다.

## 4. 만들 것
```
afpk-project/
  README.md                 # 실행법, 가정 목록
  src/sim.py                # 시뮬레이션과 검산 (표준 라이브러리만)
  tests/test_sim.py         # 3절 표 숫자를 그대로 단언
  data/returns_paths.csv    # 합성 수익률 경로
  output/                   # 그래프, 표
  report/report.md          # 6단계 사례 보고서 본문
  report/appendix_ai_log.md # AI 사용·오답·수정 기록
```
1. **시뮬레이터**: 수익률 시퀀스·인출 규칙·초기 배분을 받아 연도별 잔액을 계산. 잔액이 0 아래로 내려가면 소진 연도를 기록하고 음수로 내려가지 않게 처리.
2. **경로 비교**: (a) 3절의 2년 두 경로, (b) 20년 은퇴 기간 합성 경로 20개(첫 3년 손실 경로 포함), (c) 평균 수익률은 같고 순서만 바꾼 쌍.
3. **대안 비교**: 초기 자산의 일부를 현금(수익률 0~2% 가정)으로 두는 안, 손실 해에는 인출을 줄이는 안, 완충 현금 2년치를 두는 안. 최저 잔액·소진 연도·20년 말 잔액을 표로 비교.
4. **민감도**: 인출률(4%·5%·6%)과 현금 비중을 바꿔 결론이 유지되는 범위와 뒤집히는 지점을 표시.
5. **보고서**: 아래 5절의 6단계 구성.

## 5. 보고서 구성 (6단계)
1. **범위 합의** — 가상 고객(예: 만 60세 은퇴 직후 부부, 가상 인물)과 목표 정의. 법률·세무 판단은 범위 밖임을 명시.
2. **자료 수집** — 자산·생활비·연금 개시 시점(전부 가상). 한국거래소 투자교육 자료는 개념 설명 참고로만 인용.
3. **진단** — 평균 수익률이 아니라 **최저 잔액과 소진 시점**을 지표로 삼는다. 3절의 45만 원 차이를 대표 사례로.
4. **대안** — 4절 3번의 세 안과 현 상태 유지를 비교하고 권고안 선택 이유를 쓴다.
5. **실행** — 인출 규칙(예: 손실 해 인출 상한), 현금 완충 보충 규칙, 자동이체 일정.
6. **점검** — 연 1회 점검 항목, 잔액이 기준선 아래로 가면 취할 조치.

## 6. AI 사용 규칙
- AI(Claude)는 경로 생성, 문장 초안, 표 해설에 쓴다. **잔액 계산의 정답은 `src/sim.py`와 테스트**이고 AI가 말한 숫자는 반드시 코드로 재검산한다.
- `report/appendix_ai_log.md`에 다음을 기록: 프롬프트 요지, AI 응답, 틀린 부분, 수정 근거. 오답이 없었다면 일부러 틀리게 만들지 말고 "발견된 오답 없음, 검산 N건 일치"라고 쓴다.
- 보고서의 모든 금액은 가상이다. 실제 상품·종목 추천 표현을 쓰지 않는다.

## 7. 검증 기준 (완료 조건)
- [ ] `pytest`가 통과하고 3절 표의 700/775/1,150/820이 테스트에 포함돼 있다.
- [ ] 보고서의 모든 숫자가 `output/`의 표와 일치한다(수동 대조표를 부록에 첨부).
- [ ] 가정(연말 인출, 세금·수수료 제외, 연 1회 수익률)이 첫 장에 있다.
- [ ] 결론이 뒤집히는 조건(예: 현금 비중이 과도하면 장기 잔액이 줄어드는 지점)을 숨기지 않고 서술했다.
- [ ] 공고의 분량·형식 요건을 확인했고 부합하거나 불일치 사항을 메모했다.

## 8. 약점과 대응 (보고서에서 먼저 다룰 것)
- 가상 수익률이 현실과 다르다는 비판 → 가정을 앞쪽에 명시하고 민감도 표를 붙인다.
- 교과서적이라는 평가 → 사례 인물의 목표와 제약(연금 개시 전 공백기)을 구체화해 6단계 전체에 이어 쓴다.
- 평가에서 이 소재의 AI 필연성은 낮다는 지적이 있었다 → AI의 역할을 경로 생성·시나리오 설명·검산 기록 체계에 두고, 계산은 규칙으로 한다는 분리를 정직하게 쓴다.

## 9. 진행 방식
- 작은 단위로 커밋한다(시뮬레이터 → 테스트 → 비교 → 보고서). 푸시는 사용자가 요청할 때만.
- 막히거나 공고 요건이 이 지시서와 충돌하면 임의로 정하지 말고 질문한다.
